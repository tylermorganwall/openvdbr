# Validation

Development validation uses a temporary R library rather than replacing the
user's installed packages. Run from the package root:

```sh
R CMD INSTALL -l /path/to/library .
R_LIBS=/path/to/library Rscript --vanilla -e \
  'library(openvdbr); testthat::test_dir("tests/testthat", reporter="check")'
R_LIBS=/path/to/library R CMD INSTALL -l /path/to/library dev/consumer
R_LIBS=/path/to/library Rscript --vanilla dev/test-consumer.R
R CMD build .
R CMD check --no-manual openvdbr_13.1.0-1.tar.gz
```

The consumer compiles both C and C++, links no OpenVDB/Blosc/TBB library, and
checks ABI negotiation, ownership, invalid inputs, R handle adapters and 8,000
samples on four native threads. The R tests check sparse/active/background
values, transforms, double precision, file independence, malformed input,
CSG signs, closed mesh topology, and mesh/volume round trips.

`tests/testthat/fixtures/upstream.vdb` is generated by `dev/create-fixtures.cpp`
using upstream APIs directly. It contains a rotated/translated float grid and
a vector grid. Its constructor is separate from the provider wrappers, so the
import test does not just round-trip transforms made by the same R code.
After building the package backend, regenerate it on macOS with:

```sh
clang++ -std=gnu++17 -O2 -DNDEBUG -DOPENVDB_STATICLIB \
  -Isrc -Iinst/include -Isrc/build/include -Isrc/build/include/openvdb \
  -Isrc/vendor -Isrc/vendor/imath -Isrc/vendor/onetbb/include \
  dev/create-fixtures.cpp src/build/libopenvdbr_core.a src/build/libblosc.a \
  -Lsrc/build/runtime -lopenvdbr_tbb -lz \
  -Wl,-rpath,"$PWD/src/build/runtime" -o /tmp/openvdbr-fixtures
/tmp/openvdbr-fixtures tests/testthat/fixtures/upstream.vdb
```

The standalone diagnostic-queue test checks concurrent writes, bounded storage,
overflow reporting, truncation and draining:

```sh
clang++ -std=gnu++17 -pthread -Isrc -Iinst/include \
  src/diagnostics.cpp dev/test-diagnostics.cpp -o /tmp/openvdbr-diagnostics
/tmp/openvdbr-diagnostics
```

The initial local validation platform is macOS arm64 with R 4.6.0. Linux and
Windows build definitions are included but need execution on those platforms.

## Initial result

On macOS arm64 / R 4.6.0, `R CMD check --no-manual --no-build-vignettes`
finishes with **Status: OK** (zero errors, warnings and notes). All **101** R
expectations pass, as do the C/C++ consumer's **8,000** concurrent samples and
R handle checks. The standalone diagnostic queue test also passes. Logs are
in `dev/validation/`. `otool -L` confirms that the consumer links only R and
system libraries; the provider's only bundled runtime dependency is
`@rpath/libopenvdbr_tbb.dylib`. `nm -gU` shows only `R_init_openvdbr` exported
by the provider. The source archive is about 2.5 MiB, with about 11 MiB installed.

Local validation disabled the machine's compiler-cache wrapper within a
**temporary** Makevars file and retained its C++17 compiler setting. No global
R configuration was changed. The package itself does not set `CXX_STD`.

## Revision 13.1.0-2 renderer integration

The new volume API is exercised by rayrender's media/PBRT/C++ tests: 29,244
expectations pass with no failures or warnings and one existing empty-test skip.
Native VDB, ZIP NanoVDB and BLOSC NanoVDB seeded images agree within 1e-7,
including transformed density, independently transformed temperature, and a
stored inactive nonzero voxel. Invalid types/classes/density and truncated
compressed payloads are rejected. The original 101 provider expectations and
8,000-sample consumer test continue to pass. The aerial_explosion scene renders
at 480 x 360, 16 spp, six cores in 2.967 seconds, with no recorded path warnings.
